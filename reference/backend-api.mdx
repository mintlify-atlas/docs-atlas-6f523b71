The BAP Beta Tau backend is a REST API deployed at `https://asubap-backend.vercel.app`. All frontend requests read the base URL from the `VITE_BACKEND_URL` environment variable. Most endpoints require a Supabase-issued JWT passed as a `Bearer` token in the `Authorization` header — the token is available as `session.access_token` from the `useAuth()` hook.

```typescript
// Standard authenticated request pattern
const response = await fetch(`${import.meta.env.VITE_BACKEND_URL}/some-endpoint`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${session.access_token}`,
  },
  body: JSON.stringify(payload),
});
```

## Users

### `POST /users`

Resolves a Supabase session to an application role. Called by `AuthProvider` immediately after any auth-state change.

**Auth:** `Authorization: Bearer <token>` (required)

<ParamField body="user_email" type="string" required>
  The authenticated user's email address, sourced from `session.user.email`.
</ParamField>

**Response:** Role string or sponsor object

<ResponseField name="(string)" type="string">
  One of `"general-member"`, `"e-board"`, `"admin"`, `"pledge"`, `"alumni"` for regular users.
</ResponseField>

<ResponseField name="type" type="string">
  `"sponsor"` — present when the user is a sponsor account.
</ResponseField>

<ResponseField name="companyName" type="string">
  The sponsor's company name — present only when `type === "sponsor"`.
</ResponseField>

```bash
curl -X POST https://asubap-backend.vercel.app/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"user_email": "member@asu.edu"}'
# Response: "general-member"

curl -X POST https://asubap-backend.vercel.app/users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"user_email": "company-name@example.com"}'
# Response: {"type": "sponsor", "companyName": "Company Name"}
```

### `GET /users/summary`

Lists all registered users. Restricted to admin/e-board roles.

**Auth:** `Authorization: Bearer <token>` (required)

**Response:** Array of user summary objects

<ResponseField name="email" type="string">The user's email address.</ResponseField>
<ResponseField name="name" type="string">Display name.</ResponseField>
<ResponseField name="role" type="string">Application role string.</ResponseField>
<ResponseField name="rank" type="string">Member rank (e.g., `"inducted"`, `"pledge"`, `"alumni"`).</ResponseField>

```bash
curl -X GET https://asubap-backend.vercel.app/users/summary \
  -H "Authorization: Bearer <token>"
# Response: [{"email":"...","name":"...","role":"general-member","rank":"inducted"}]
```

---

### `POST /users/delete-user`

Permanently removes a user account. Restricted to admin/e-board roles.

**Auth:** `Authorization: Bearer <token>` (required)

<ParamField body="user_email" type="string" required>

</ParamField>

```bash

  -H "Content-Type: application/json" \

```

## Events

### `GET /events`

Returns the event list. The response shape differs based on the caller's role.

**Auth:** `Authorization: Bearer <token>` (required)

**Response:** `MemberEvent[]` for members/sponsors, `AdminEvent[]` for e-board

<Tabs>
  <Tab title="MemberEvent fields">
    <ResponseField name="id" type="string">Event identifier.</ResponseField>
    <ResponseField name="event_name" type="string">Event title.</ResponseField>
    <ResponseField name="event_description" type="string">Description text.</ResponseField>
    <ResponseField name="event_location" type="string">Venue or location string.</ResponseField>
    <ResponseField name="event_date" type="string">ISO date string (`YYYY-MM-DD`).</ResponseField>
    <ResponseField name="event_time" type="string">Time string (`HH:MM:SS`).</ResponseField>
    <ResponseField name="event_hours" type="number">Credit hours for attendance.</ResponseField>
    <ResponseField name="event_hours_type" type="string">Hour category (e.g. `"professional"`, `"service"`).</ResponseField>
    <ResponseField name="rsvp_count" type="number">Aggregate RSVP count.</ResponseField>
    <ResponseField name="attending_count" type="number">Aggregate attendance count.</ResponseField>
    <ResponseField name="user_rsvped" type="boolean">Whether the current user has RSVP'd.</ResponseField>
    <ResponseField name="user_attended" type="boolean">Whether the current user attended.</ResponseField>
    <ResponseField name="can_check_in" type="boolean">Whether check-in is currently available.</ResponseField>
  </Tab>
  <Tab title="AdminEvent additional fields">
    <ResponseField name="event_lat" type="number">Check-in geofence latitude.</ResponseField>
    <ResponseField name="event_long" type="number">Check-in geofence longitude.</ResponseField>
    <ResponseField name="event_rsvped" type="string[]">Array of user IDs who RSVP'd.</ResponseField>
    <ResponseField name="event_attending" type="string[]">Array of user IDs who attended.</ResponseField>
    <ResponseField name="is_hidden" type="boolean">Whether event is hidden from non-admins.</ResponseField>
    <ResponseField name="check_in_window" type="number">Minutes before/after event start that check-in is open.</ResponseField>
    <ResponseField name="check_in_radius" type="number">Geofence radius in meters.</ResponseField>
  </Tab>
</Tabs>

```bash
curl -X GET https://asubap-backend.vercel.app/events \
  -H "Authorization: Bearer <token>"
```

### `GET /events/:eventId/participants`

Returns detailed RSVP and attendance lists with user emails. **E-board only.**

**Auth:** `Authorization: Bearer <token>` (required, e-board role)

**Path param:** `eventId` — the event's string identifier.

**Response:** `EventParticipants`

<ResponseField name="event_id" type="string">Event identifier.</ResponseField>
<ResponseField name="event_name" type="string">Event name.</ResponseField>
<ResponseField name="rsvped_users" type="array">
  Array of `{user_id, name, user_email}` for users who RSVP'd.
</ResponseField>
<ResponseField name="attending_users" type="array">
  Array of `{user_id, name, user_email, checked_in_at?}` for users who attended.
</ResponseField>
<ResponseField name="rsvp_count" type="number">Total RSVP count.</ResponseField>
<ResponseField name="attending_count" type="number">Total attendance count.</ResponseField>

```bash
curl -X GET https://asubap-backend.vercel.app/events/42/participants \
  -H "Authorization: Bearer <token>"
```

Updates a sponsor's about text and links.

**Auth:** `Authorization: Bearer <token>` (required, sponsor role for own profile)

**Path param:** `name` — the sponsor's company name.

<ParamField body="about" type="string" required>
  Updated company description (max 500 characters).
</ParamField>

<ParamField body="links" type="string[]" required>

  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"about": "We build software.", "links": ["https://acme.com"]}'

## Links

### `GET /links`

Returns dynamic URL values stored in the backend (used to avoid hardcoding URLs in the frontend).

**Auth:** `Authorization: Bearer <token>` (required)

**Query params:**

<ParamField query="link_name" type="string" required>
  The identifier for the desired link. Example: `forms`.
</ParamField>

**Response:** `[{ link: string }]` — an array with a single object containing the URL.

```bash
curl -X GET "https://asubap-backend.vercel.app/links?link_name=forms" \
  -H "Authorization: Bearer <token>"
# Response: [{"link": "https://docs.google.com/forms/..."}]
```

## Error Handling

All endpoints return standard HTTP status codes. Common error shapes:

| Status | Meaning |
|---|---|
| `400` | Bad request — missing or invalid body parameters |
| `401` | Unauthorized — missing or expired Bearer token |
| `403` | Forbidden — valid token but insufficient role, or archived member |
| `404` | Resource not found |
| `500` | Internal server error |

Error responses include a JSON body: `{ "error": "Human-readable message" }`.

<Warning>
  The `POST /users` endpoint returns `403` with `{ error: "Member is archived" }` when an archived member attempts to authenticate. `AuthProvider` propagates this as `authError` in the auth context without clearing the session — the `/auth/Home` page is responsible for displaying the error and signing the user out.
</Warning>
